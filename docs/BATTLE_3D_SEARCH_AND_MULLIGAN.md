# 手牌、检索展示与开局再战修正

本次“再战”指开局没有基础宝可梦时，公开手牌、洗回牌库并重新抽牌。

## 画面调整

- 手牌基础圆弧半径从 9.5 增至 11，最大展开角由 18° 收至 15°；基础卡牌尺寸增加 12%，实际显示继续按可用高度和宽度适配，保持两端完整和相邻间距均匀。
- 移除竞技场右下角的数量角标。
- 公开检索结果使用统一的圆角底板、背景压暗、大卡面和卡面下方的结果说明。少量卡牌宽度为 168px；多张结果按空间缩放。底板和卡牌位于同一三维视口，卡图不受背景压暗影响，标题和说明保持屏幕 UI 的清晰度。
- 检索展示期间缩放窗口，会同步更新面板、卡面和说明的位置；待出发的卡牌保持隐藏，避免提前叠在牌库上。

## 再战生命周期

原来的非最终开局手牌没有真实手牌落点，使用普通运动卡牌的屏幕排布，并在单个事件结束时消失。新增 `BattleMulligan3D`，在抽出、公开和洗回过程中保留同一组临时实体，使用正常手牌的扇形、尺寸和朝向。

对手临时卡牌还存在我方尺寸留下的最小尺寸约束，造成约 30px 的整体偏移；现在按所属玩家同步更新尺寸约束。对手的真实卡面只在公开事件开始后绑定；本地交接会遮挡私有手牌，视角切换、重同步和退出会清理临时实体。减少动画保留公开结果的阅读时间，再战结束后恢复正常任务提示。

Workbench 新增“我方连续再战”“对手连续再战”和“公开检索结果”。再战使用原生规则种子 `2026071608`，可重复播放三次连续再战。检索结果支持原有 0%、50%、100% 检查点。

## 验证记录

Godot 14 项契约、三维图形契约、UI 预览和源码边界检查通过。新增检查覆盖双方视角各三次连续再战，共六次公开；临时手牌与最终正常手牌的包围区域误差约 0.000244px，取消和隐私遮挡检查通过。

检索展示覆盖 0、1、2、7 张卡牌，在 1600×900、900×540、2000×900 下连续调整窗口，共 12 组检查通过。原有五档分辨率的对称布局、密集手牌、拖拽、中央闪卡和对象池检查继续通过。

性能探针在 RTX 4070 Ti、1920×1080、Compatibility 实际渲染下分别采集高、中、低档各 300 帧；P95 为 16.987、16.982、33.604ms，绘制调用为 308、308、209，均满足对应预算。

10 套 Challenge 卡组终局回归，以及 LAN 42 回合、Relay 41 回合完整对局回归通过。Windows 与 Android 调试包已重新导出，导出后的 Windows 启动、原生运行库、网络和发布契约检查，以及 APK 元数据和 ARM64 载荷检查通过。
