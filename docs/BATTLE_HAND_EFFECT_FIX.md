# 卡牌效果结算中的手牌重复显示修复

日期：2026-09-14。

## 根因

使用电气发生器时，原生规则会先从手牌移走训练家，再依次等待能量选择和目标分配；最终返回的事件包含整次操作。表现层在此之前已经显示了移走训练家后的手牌，却再次用最终事件匹配旧手牌。

几个共用问题叠加后产生了截图中的重复能量卡和数量不一致：

- 无来源的附能通知在第二次标准化时，把补齐的空端点误认为有效来源，默认解释为从手牌附能。
- 训练家已离开手牌或索引过期时，手牌源匹配会回退到不相关的卡；混合有效、过期索引还可能重复匹配第一种卡。
- 洗牌事件无条件重置手牌视觉身份，使未离开手牌的卡失去连续性。
- 同一次牌库附能的选择事件和附能事件会重复推进表现；仅跳过运动仍会重复扣手牌计数、增加弃牌计数。
- 事件去重原本晚于手牌身份重建，重复包仍能影响刚抽到的同名卡。

## 修复方式

事件标准化只承认可定位的牌区、牌位或有效索引；空通知保持零张卡，牌位来源不会补成手牌。手牌源匹配按每一张卡分别匹配索引与卡牌 ID，已知 ID 匹配失败时不再借用其他卡。

手牌身份和动画暂存共用一次规则：根据“此前手牌 + 本批加入手牌 - 最终手牌”确定仍需展示离开的实体。这样既能保留未使用的同名训练家，又能区分弃掉后重新抽到的同名卡。最终手牌取自队列拥有的目标视图，不读取继续变化的规则状态。

进入表现队列前排除已经反映在选择中间局面里的离手事件，并合并非公开选择与后续相同附能的表现。手牌实体、HUD 和牌堆数量使用同一组事件。隐藏手牌只通过数量判断，不读取对方私有卡面。洗牌不再重置手中卡的身份，重复事件在身份重建之前即被排除。

规则、卡牌效果、存档和网络消息格式没有改变。

## 回归

新增 `godot/tests/battle_card_effect_hand_contract.gd`，直接驱动原生规则和真实表现队列，覆盖 42 个组合：

- 电气发生器附两张到同一目标、分配给两个目标、只附一张、不附能、取消、保留同名训练家、使用最后一张手牌。
- 能量回收、高级球、巢穴球、能量转移、茸茸羊附能、博士的研究。
- 对方观察视角、标准／快速／减少动画，以及最终结算包重复送达。

逐帧检查手牌视觉身份、三维实体数量、位置稳定性、卡面和交互索引、HUD 数量、私有卡面遮挡及完成后运动实体清理；正常动画模式必须实际观察到卡片运动，避免仅验证动画结束后的静态局面。

该回归已经加入 `tools/test_godot.ps1` 和 `tools/test_battle3d_graphics.ps1`。独立重放命令：

```powershell
& .tools/godot-4.7/Godot_v4.7-stable_win64_console.exe --path godot --script res://tests/battle_card_effect_hand_contract.gd
```

输出：`build/generator-hand/validation-graphics.json`、`validation-headless.json`，以及实际渲染的附能中途和完成截图。无图形检查加 `--headless`；截图和实际三维渲染检查必须保留图形模式。
