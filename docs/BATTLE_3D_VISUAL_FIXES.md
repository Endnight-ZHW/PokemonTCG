# 三维视觉与动画修正 · 2026-09-13

后续四项截图反馈的修正记录见 [抽牌与布局修正](BATTLE_3D_DRAW_AND_LAYOUT.md)。该轮更新了下文的分片洗牌、手牌排布和牌区对齐方式。

针对实际对局截图中的五项问题，这轮修正了光照合成、手牌空间姿态、牌堆体积、洗牌轨迹和双方牌位网格。

| 用户反馈 | 修正 |
| --- | --- |
| 卡图发白、亮度过高 | 使用中性主光，柔和填充在同一个光照通道计算；降低卡套反光。实测 50% 灰由约 63% 恢复至约 49%，不同画质不再改变卡面亮度 |
| 开局洗牌只显示半副，运动像二维 | 拆分、交错、桥式回落和切牌直接驱动 `Transform3D`；每包保留实际体积，完整包围区域约束在视口内 |
| 双方手牌缺少三维感 | 实体卡牌沿空间扇形摆放，减少朝镜头正对的角度，露出纸边与接触阴影；小屏按备战区与屏幕边界收纳，选中时抬起 |
| 牌库、弃牌区没有堆叠厚度 | 按实际数量生成有厚度的纸层组，最多六个实体；最上面一张单独存在，抽牌时保留下方牌堆 |
| 双方牌位不齐 | 使用同一组世界坐标列及实体尺寸；远近大小由透视相机产生，移除旧二维宽度与横向展开的重复影响 |

同时修正了暂存手牌、抽牌落入对方手牌、整组宝可梦换位时的角度或位置跳变：表现快照保存三维姿态，移动和交接继续使用该姿态。牌区标题、空位文字也根据实际投影定位。纸边细纹加入导数抗锯齿，避免低分辨率下出现黑色波纹。

亮度问题通过实际灰阶渲染定位，并参考了 [Godot 4.7 Compatibility 光照与 sRGB 合成实现](https://github.com/godotengine/godot/blob/4.7-stable/drivers/gles3/shaders/scene.glsl)。没有修改原始卡图。

新增 `battle_3d_visual_contract.gd`，只在真实图形设备下运行，检查：

- 深、中、浅灰的亮度和高、中、低画质的一致性。
- 双方备战列、牌堆列在世界坐标中的对齐及实体尺寸。
- 双方手牌有三维网格，二维卡图绘制已隐藏。
- 开局洗牌逐帧的三维姿态、旋转、厚度、完整视口边界，以及完成、重同步后的清理。
- 1600×900、900×540 和用户截图对应的 2560×1392；其他契约及预览继续覆盖 1280×720、2000×900 和安全区。

Godot Workbench 新增“三维开局洗牌”按钮，可重复播放；“三维细节检查”保留满备战、20 张手牌、多附件和复合状态场景。

实际图形采样：RTX 4070 Ti、1920×1080，高、中、低档 P95 分别为 16.675ms、16.675ms、33.348ms，均在现有帧预算内。完整结果保存在 [性能记录](../build/battle3d-performance.json)，灰阶与逐帧检查保存在 [视觉契约记录](../build/battle3d-visual-contract.json)。Android 真机触控、持续帧率及温升仍待接入设备验收。

完整 Godot 契约、10 套 Challenge 卡组、LAN/Relay 完整对局和实际图形预览均通过。Windows、Android 调试导出已更新，Windows 启动/原生运行库/网络/发布契约及 APK 静态检查通过，Android 设备运行检查因未连接真机跳过。[当前交付文件与 SHA-256](../build/battle3d-visual-fixes/delivery.json)。
