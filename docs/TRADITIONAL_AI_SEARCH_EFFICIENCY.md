# 传统 AI 搜索效率优化：收尾记录

2026-09-12 按用户“当前验收太慢，需要尽快收尾”的要求结束剩余长对局及待启动的大批验收。
代码已合入当前工作分支，工程验证通过；本轮按缩减验收范围收尾，**没有宣称原棋力验收通过**。
产品 `godot/bin` 继续使用原运行库；新版本四份构建产物保存在隔离目录，可用于后续评估。

## 实现与范围

| 层级 | 最终调整 |
| --- | --- |
| Godot 与控制器 | 保留五秒预算、异步取消与原生生命周期；维护公开信息、计划前提与防循环。 |
| 静态知识和请求缓存 | 建立进化／角色／资源索引；精确缓存区分玩家、样本、RNG、规则、选牌策略与历史。 |
| `DecisionSearchContext` | 共享采样根、候选模拟终态、评分和已完成的场景结果，连接初始方案与渐进搜索。 |
| `DecisionBudget` | 初始阶段最多 20%，末尾预留 5%、最多 250 ms；中断评分不参与完整比较或写入计划缓存。 |
| v3 搜索 | 快速排序后详细评分短名单，保护根动作和资源路线；共同样本上比较反击与接续。 |
| 路线保留与循环处理 | 同时保留传统和战略评分看好的路线；剪除经完整状态核对的纯能量转移循环。 |
| Arena | 修复中断后剩余座位组合的恢复，仅补跑未完成比赛，保留持久化分片。 |

独立 `turn_beam_v2` 入口保留；`RulesSession` 继续使用现有分叉和写时复制。
Action 4、ChoiceView 2、Snapshot 3、网络协议 6、卡牌规则、牌组与作者策略权重保持一致。
没有引入模型训练或神经网络推理。最后一个策略实现为 `ff20a05`，整合源码为 `c4034fd`。
开发环境整理提交 `62e6d03` 随合入保留。

## 性能证据

第一阶段在原 302 条请求上预热一次、测量三轮，共 906 次正式决策，动作、选牌、计划及评分零差异。
固定工作搜索 P95 从 **5106.81 ms 降至 2965.36 ms（下降 41.9%）**，通过第一阶段 30% 目标。

旧 final-04 已完成 313 条请求、预热一次及测量三轮的单局串行回放；每构建每线程配置共 939 次正式请求。

| 全部请求 P95 | 基线 | 旧 final-04 |
| --- | ---: | ---: |
| 单线程 | 4412.00 ms | 1577.20 ms |
| Windows 三线程 | 1935.04 ms | 1077.20 ms |

三线程中位耗时从 34.27 ms 升至 162.33 ms，反映部分简单局面增加比较工作。
上述延迟仅属于旧 final-04；最新候选的独立延迟队列已取消，不能直接沿用旧数值。
Android 没有连接真机，交叉编译不代表手机延迟通过。

## 棋力结果与停止范围

旧 final-04 完成两批：**800 局主对局 + 800 局固定对手对照**。
主对局 **418 胜、382 负，得分率 52.25%**；当时预声明的顺序校正区间为 **48.875%–55.500%**。
各牌组固定对手差值均不低于 −5 个百分点，但总体得分率及区间下界尚未达到晋级要求，状态为 `inconclusive`。
提前结束后保留这一历史检查结果，不将其解释为本次停止规则下重新完成的统计验收。

第三批已持久化 **328 / 400** 局，缺少完整批次与配套对照，
只保留原始数据，不并入晋级结论。所有五个已运行目录的分片哈希、任务索引与重试记录已核验；
已持久化结果没有结构错误或截断。

剩余第三批及其对照、最新版单／三线程完整计时、最新版最多三批独立棋力队列均停止或取消。
后台对局和自动长验收进程已结束，旧入口设有本次收尾标记，避免自动重启。
最新候选的棋力提升仍为**未证实**，产品运行库没有获得发布资格，本轮没有更新 `godot/bin`。

## 消融与失败案例

精确缓存单独开关的四局面样本没有明显 P95 收益；该开关不覆盖静态索引、采样根与场景共享。
双评分路线保留在完整轨迹上改变 16 条计划，其中 11 条根动作变化、零选牌变化；
完成三个样本且满足风险下限的比较计数从 69 增至 83。
开发 guided-01 曾跳过获胜的当前方案，控制器回归发现后已修复。
索引 265、280、283 曾出现能量来回搬运；保守剪枝后公开采样重放均不再循环。
这些案例及固定工作消融用于解释变化，不构成棋力提高的因果证据。
