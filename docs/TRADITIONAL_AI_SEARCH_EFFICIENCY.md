## 验收口径与范围

此次重新按用户确认的实测门槛审阅已有完整数据，**不等于统计上证明总体棋力不劣**。
原预声明顺序校正区间仍为 48.875%–55.500%，原来要求 53% 和区间下界高于 50% 的严格棋力验收没有被改写。
新的工程发布标准只要求整体实测至少 50%，同时保留规则正确性、原有牌组退化限制和五秒桌面延迟门槛。

最新版实验另启动了一次固定 40 局、十套同牌组与交换座位／先后手的短测。
在预设的 15 分钟上限处停止，持久化 **23/40** 局，未形成完整样本，
没有用于判断通过、没有并入 final-04 的 800 局，也没有追加批次或加时。
所有旧队列、新短测与原始分片均保留；当前没有后台验收任务。

## 性能

第一阶段：302 条请求预热一次、测量三轮，906 次正式决策的动作、选牌、计划和评分零差异。
固定工作搜索 P95 从 **5106.81 ms 降至 2965.36 ms（下降 41.9%）**。

本次发布的 final-04 已完成 313 条完整公开请求、预热一次、测量三轮的单局串行回放，
每个构建、每种线程配置各 939 次正式请求，双方均使用 5000 ms 预算。

| 全部请求 P95 | 原基线 `71d02fa` | 发布版本 final-04 |
| --- | ---: | ---: |
| 单线程 | 4412.00 ms | 1577.20 ms |
| Windows 三线程 | 1935.04 ms | 1077.20 ms |

三线程全部请求 P95 下降约 44.3%；P50 从 34.27 ms 升至 162.33 ms，部分简单局面增加了比较工作。
这些数字来自独立计时，不混用并发对局耗时。Android arm64 构建通过，尚无真机延迟结论。

## 实现和验证

- 不可变进化／角色／资源索引；请求内精确缓存区分玩家、隐藏样本、RNG、规则、策略及历史。
- `DecisionSearchContext` 共享采样根、初始候选终态、评分、反击和接续；独立 v2 保留。
- 初始阶段最多 20%，末尾预留 5%、最多 250 ms；中断评分不参与完整比较或写入计划。
- 快速排序后详细评分短名单，保护根动作及资源准备路线；保持规则分叉和写时复制。
- 109 个战术场景、可控时钟预算、取消、缓存隔离和原有 88 项研究测试通过；选定发布策略后再次运行全部研究测试并通过。
- 独立 v2 的 313 条回放与基线零语义差异；三处历史生命周期案例通过 AddressSanitizer。
- 四份原生库构建和机器类型核验通过；实际发布目录的 Godot 原生协议、十套牌回归及源码／产品边界检查通过。

Action 4、ChoiceView 2、Snapshot 3、网络 6、卡牌规则、牌组和作者策略权重保持一致，未引入神经网络。
缓存单独开关的四局面消融未显示明显 P95 收益；41.9% 提速不能单独归因于该缓存开关。
此前实验中的获胜方案筛选与能量循环案例、关闭开关对照及全部失败记录保留在开发分支和原证据目录。
