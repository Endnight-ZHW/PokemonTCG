# 传统 AI 搜索效率

基线为 `71d02fa06c7bb4ac80cbe019e83a2e772373965b`。客户端仍请求 5000 毫秒，
Action 4、ChoiceView 2、Snapshot 3、Protocol 6、卡牌内容及作者策略权重不变。
本文区分保持决策的计算优化与会改变决策的渐进搜索，验收结果分别记录。

## 架构与边界

| 层 | 职责与本轮调整 |
| --- | --- |
| Godot 适配器 | 保留异步请求、取消代次、控制器生命周期与 5000 ms 请求预算。 |
| `ChallengeController` | 维护公开信息记忆、计划前提与防循环；创建请求上下文，先取得合法备用动作。 |
| `DecisionSearchContext` | 共享采样根、初始候选终态、精确求值、已完成的场景结果和工作量计数。 |
| `turn_beam_v2` | 保留独立入口；也向 v3 提供有界初始方案和实际模拟终态。 |
| `strategic_intent_v3` | 合并初始方案与战略意图，分批继续同一棵束搜索树，比较反击及下回合接续。 |
| `ChallengeSearchProvider` | 统一排序、完整评分、选牌策略与模拟适配；计算过程不改变卡牌规则。 |
| `RulesSession` | 继续负责合法性及状态推进，沿用搜索分叉和写时复制。 |

静态知识保留在控制器配置的生命周期中。阶段二进一步将卡牌效果和支援者类型解析移入
不可变索引，避免每个请求重新预热整张卡表；未知卡号返回空特征，不在工作线程中懒插入缓存。

## 精确计算优化

- 配置时构建进化关系及名称索引；一次攻击手分析复用相同费用的能量安排。
- 只遍历可用能量，跳过同名能量的重复评分；已经满足费用时保留原结果并提前返回。
- 请求级 `DecisionSearchContext` 保留 COW 状态，复用区域计数、攻击手分析、
  局面评分、状态指纹及继续执行前提。状态修改会分离存储，缓存持有原值，避免地址复用误命中。
- 评估键区分状态、规则会话依据、玩家、RNG 和评分策略。区域计数仅依赖两组精确区域数组。
  请求结束即释放动态缓存；控制器只跨请求共享不可变知识和既有的公开信息计划记忆。

冻结的第一阶段构建对 302 条公开请求预热一次、正式测量三轮。双方分别维护每个座位的控制器，
完整回放请求以保持奖赏知识及计划记忆，并交替执行先后顺序。以下是单线程、固定工作模式的数据：

| 指标 | 当前基线 | 第一阶段 | 变化 |
| --- | ---: | ---: | ---: |
| 搜索 P50 | 1697.42 ms | 1070.93 ms | −36.9% |
| 搜索 P95 | 5106.81 ms | 2965.36 ms | −41.9% |
| 所有决策 P95 | 3869.76 ms | 2337.88 ms | −39.6% |
| 缓存命中 P95 | 372.99 ms | 269.71 ms | −27.7% |

906 次正式核对没有动作、选牌、计划序列或评分差异。第一阶段的 30% 提速目标通过。
原始证据在 `build/traditional-ai-efficiency/stage1-timing`。该结果不代表渐进搜索的棋力或游戏线程配置的延迟。

## 渐进搜索

`DecisionBudget` 统一覆盖准备、候选、选牌、反击、接续和验证。初始策略阶段最多使用
总预算的 20%，末尾预留 5%、最多 250 毫秒供验证和返回；未使用的初始时间留给后续搜索。
预算为零时执行固定规模搜索，适合确定性回归；显式取消与预算到期分别处理。

初始策略以有界 v2 搜索提供可用动作和模拟终态，按平台允许的线程数并行采样。
v3 接收全部已完成的初始候选，直接接续这些状态，按 `node_budget`
大小分批展开，并保留尚未完成的层、父节点和动作索引。根动作分别保留准备路线；
常规深度沿用原有范围，准备接近完成时可延伸两步，总深度最多 10。
根动作保底不会占满束宽，其余名额继续按方案评分分配给准备路线。

动作先进行低成本排序，再详细评分前 16 项及额外受保护的终结、资源和换位路线。
反击和接续优先比较当前方案与前三个竞争方案。双方使用相同样本编号及完整评估阶段，
先处理一个样本，达不到风险下限即淘汰；其余样本可并行计算，按固定顺序归并。
完成的序列回放和交换结果在请求内复用。初始搜索与后续比较使用同一组隐藏信息采样种子；
反击和接续阶段也保护攻击及结束回合，避免准备动作挤掉所有能到达回合边界的路线。

截止后不会切换评分公式；未完成评分带显式状态，不参与完整比较或进入缓存。
每次改进均先进行权威规则验证，再替换当前可提交方案。另一条路线仅仅先执行了
END_TURN，不能作为优于尚未完成的准备路线的证据。
若截止跨越多个采样任务，所有保留样本退到共同完成的评分阶段；尚未完成根动作覆盖的样本
不参与投票。验证器持有动作副本，规则推进后不再引用被失效的合法动作缓存。

独立 `turn_beam_v2` 保留。内部评估可设置 `internal_anytime_search=false` 关闭新的初始预算和渐进调度，
或设置 `internal_search_memoization=false` 关闭精确求值备忘。`internal_full_diagnostics=true`
可要求唯一动作的快速出口也计算战略事实，供资源模型诊断使用。

## 评测口径

Arena 新增 `--time-budget-ms` 与 `--search-worker-mode single|gameplay`，双方必须相同。
时间预算被直接传入控制器，watchdog 只处理基础设施超时。固定工作模式保留确定性标记，
时间模式标记为墙钟预算。游戏线程模式最多并发四局；冒烟模式仍强制每次搜索一个线程。

`native_performance_counters` 增补实际规则动作、选择结算、详细评分数量、各类缓存命中、
完整方案比较、候选批次、三个阶段的耗时及被中断的评估数量。
`budget_last_stop_reason` 区分初始阶段上限、搜索上限、硬截止及显式取消；
`reused_initial_plans`、排序缓存命中和完整比较数量用于核实节省的工作去了哪里。
`node_budget` 是候选构建规模，不能作为所有搜索工作的总成本；性能报告同时保留实际工作量和时间。

阶段二的对局、发布库和最终验收正在进行。开发试验与正式验收使用独立目录，
失败或提前停止的开发批次不纳入验收统计。
