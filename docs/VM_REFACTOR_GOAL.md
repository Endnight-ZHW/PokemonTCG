# PTCG Rules VM Refactor Goal

## Objective

Upgrade the rules layer into a versioned, stack-driven VM that can resolve nested card effects, triggers, modifiers, choices, rollback, and AI simulation without relying on legacy `effect_type` dispatch at runtime.

The target architecture keeps Godot as the complete offline runtime and Python as the compiler, reference runtime, AI/training oracle, and regression source. Runtime execution should consume `compiled_effects`; raw effect metadata remains available for display, migration audit, and export compatibility only.

## Current Baseline

- VM IR is versioned and rejects unknown ops or native VM commands carrying legacy `effect_type` args.
- Godot supported legacy effect types and native VM op support lists live in `VMContract`; `EffectEngine` only forwards support queries and registers the contract's native ops.
- Python and Godot both have command registries and continuation registries.
- Python `VMInterpreter` owns command execution, pending-choice wrapping, callback continuation chaining, registered continuation dispatch, and default continuation registry wiring; `ResolutionStack` stays as the LIFO/context/abort state container with compatibility entrypoints and injectable registry/interpreter dependencies.
- Godot `EffectEngine` acts as a VM facade with command/continuation modules under `godot/rules/vm/`.
- Godot VM module construction, native op registration, and continuation registration live in `VMRuntime`; `EffectEngine` is now a compatibility facade over that runtime container instead of owning VM assembly.
- Godot `EffectEngine` no longer mirrors VMRuntime submodules as facade fields; direct module inspection and service wiring goes through `effect_engine.runtime.*`, while the facade keeps only compatibility methods for support checks, stack resolution, and choice application.
- Godot structural tests now reject concrete VM handler prefixes such as `_cmd_*`, `_continue_*`, `_request_*`, `_register_*`, and `_execute_*` returning to the `EffectEngine` facade.
- Godot `VMInterpreter` owns the resolution loop, VM effect execution, choice validation, and continuation resume; `EffectEngine` keeps only compatibility wrapper entrypoints.
- Godot VM result dictionaries are constructed through `VMResult`, so VM command/continuation modules no longer depend on `EffectEngine._ok/_fail`.
- Godot trainer command and continuation modules receive `CardCatalog` explicitly; they no longer keep weak references to the `EffectEngine` facade.
- Godot energy command and continuation modules receive `CardCatalog`, `VMTriggerCommands`, and `VMEnergyCommands` explicitly; attach/relocate flows no longer reach through the `EffectEngine` facade for services.
- Godot look-top command and continuation modules receive `CardCatalog` and `VMEnergyCommands` explicitly; look-top deck and attach-energy flows no longer keep weak references to the `EffectEngine` facade.
- Godot coin command module receives `CardCatalog` and `VMCombatDamage` explicitly; coin branch, repeated damage, until-tails damage, double-KO, and energy-discard flows no longer keep weak references to the `EffectEngine` facade.
- Godot board command and continuation modules receive `CardCatalog`, `VMBoardCommands`, `VMCoinCommands`, and `VMCombatDamage` explicitly; switch, coin, damage, heal, and discard-attachment continuations no longer reach through the `EffectEngine` facade for services.
- Godot combat command modules receive `VMTrainerCommands`, `VMBoardCommands`, and shared `VMCombatDamage` explicitly; damage choice, conditional search, combo damage, formula, and conditional helpers no longer keep weak references to the `EffectEngine` facade or local result-helper functions.
- Godot shared VM helper/command modules route command-result dictionaries through `VMResult`; choice request, zone helper, draw, status, modifier, trigger, continuation registry, and combat modules no longer define local `ok`/`fail` helpers.
- Python attack effects enter a single `ResolutionStack`; final attack damage and KO checks resolve as stack frames.
- Python no-promotion attack completion now resolves the attack end-turn transition from a `FinalizeAttackTurn` stack frame.
- Python promotion-delayed attack completion is stored in `resolution_stack.context`, so snapshot/clone/rollback preserve the pending end-turn state.
- Python attack completion no longer uses `GameEngine._finish_attack_turn`; promotion resume executes a `FinalizeAttackTurn` frame through a `ResolutionStack`.
- Godot attack end-turn completion uses a serializable `finalize_attack_turn` frame; promotion-delayed attack completion preserves and consumes that frame from `ResolutionStack`.
- Godot attack declaration, confusion/dazzle attack-failure checks, attack VM stack construction, final damage, after-damage trigger commands, and attack turn-frame consumption live in `VMAttackSettlement` instead of `GameEngine`; KO handling is delegated directly to `VMKnockoutSettlement`.
- Godot turn settlement logic for end turn, checkup, draw/start-turn transition, and attack finalize-turn completion lives in `VMTurnSettlement`; `VMAttackSettlement` no longer calls back into the `GameEngine` facade.
- Godot KO, prize-taking, empty-board promotion, and winner checks live in `VMKnockoutSettlement`; `GameEngine`, attack settlement, and turn settlement share that service explicitly instead of using weak references or attack-settlement proxy methods.
- Godot promotion settlement and promotion-delayed attack finalization live in `VMPromotionSettlement`; `GameEngine` dispatches `PROMOTE` to the settlement service instead of owning the post-promotion attack/turn continuation path.
- Godot trigger command execution for after-damage triggers, `POKEMON_KO` Exp Share pre-discard movement, and `ON_ATTACH` Jet Energy switching lives in `VMTriggerCommands`; trigger collectors return `trigger_*` VM command specs, source-level coverage rejects direct board mutation returning to the collector/hook region, and command specs resolve through the active `ResolutionStack` when available.
- Godot trigger command normalization and resolution now return structured `VMResult` failures; malformed trigger payload wrappers, unknown trigger ops, public action, VM energy attachment, attack finalization, KO, choice, and checkup settlement propagate trigger failures to `StepResult` so transaction rollback can restore the pre-action state.
- Godot trigger command normalization now matches Python's trigger boundary: shorthand trigger payloads normalize to registered `trigger_*` VM ops, explicit non-`trigger_*` `{op,args,branches}` command specs fail with `invalid_trigger_op` before execution, and `exclusive_group` payloads keep the first stable-priority trigger command group only after a payload actually contributes at least one command spec.
- Godot `AFTER_DAMAGE` hook collection for Miracle Energy and reactive thorns is owned by `VMTriggerCommands`; `VMDamageModifierHooks` is scoped back to damage modification.
- Godot retreat-cost modifiers resolve through `VMRetreatModifierHooks` and `VMModifierManager.CAN_RETREAT`; `RulesValidator` no longer owns the `conditional_zero_retreat` branch.
- Godot max-HP modifiers resolve through `VMPokemonStatHooks` and `VMModifierManager.MAX_HP`; `PokemonState.current_hp()` delegates instead of owning HP-boost branches.
- Godot pending attack choices are covered across `GameState.snapshot()` roundtrip; restored states preserve the pending request, attack stack frames, and final attack completion.
- Godot optional attack choice cancellation is covered as a stack continuation case: cancelling without an action checkpoint skips only the optional continuation, preserves the attack-finalize frame, clears the pending request, and finishes the attack turn instead of rolling back the whole attack.
- Python pending attack choices now write a serializable pending request plus finalize/continuation frame summary into `state.resolution_stack`, so snapshot/clone/export paths can see the paused attack continuation.
- Python cancellable trainer choices now store a serializable pre-action checkpoint in `resolution_stack.context`; cancellation restores the action snapshot, action log, event stream, and RNG state instead of relying on pending-card-only compensation.
- Python cancellable action checkpoints explicitly carry event-stream entries in addition to the serialized state snapshot, so cancellation restore no longer depends on event data being implicit inside the snapshot payload.
- Python public action/choice transaction capture, failed-step rollback, cancel checkpoint serialization/restore, pending-choice stack serialization, RNG restore, and event-stream restore live in `VMTransactionManager`; `GameEngine` delegates the transaction boundary instead of owning snapshot mutation helpers.
- Python and Godot public action rollback tests now cover a VM command sequence that mutates hand/deck, advances RNG, and then fails in a later command; both runtimes also cover attack final-damage mutation followed by trigger settlement failure. Failed actions restore state, RNG, action log/event stream, and suppress rolled-back events/pending choices.
- Python non-attack KO settlement now propagates `POKEMON_KO` trigger command normalization/execution failures into failed public `StepResult`s, so the transaction manager rolls back state, RNG, action log, event stream, pending choices, and emitted events instead of continuing KO/prize settlement.
- Python `ON_ATTACH` trigger command execution failures now fail the public attach-energy action instead of being appended to a success log, so `VMTransactionManager` rolls back the already-attached card, RNG, action log, event stream, pending choices, and emitted events.
- Python stable `ChoiceRequest` construction, default auto-choice policy, legacy payload conversion, and pending trainer-card consume/cancel behavior live in `VMChoiceManager`; `GameEngine` keeps compatibility wrapper methods but no longer owns concrete choice-type branching.
- Python promotion settlement, non-attack KO checks, attack finalize-turn frame execution, event slicing, `ActionResult` to `StepResult` conversion, and multi-step merge logic live in `VMSettlementManager`; `GameEngine` delegates settlement boundaries instead of owning those post-dispatch helpers.
- Python public action enumeration, setup actions, retreat payment generation, stadium activation checks, and stale action-reference validation live in `VMActionAvailability`; `GameEngine` delegates legal-action availability instead of owning concrete legality branches.
- Godot cancellable trainer choices also store a serialized `cancel_action_checkpoint` in `ResolutionStack.context`; cancellation restores the pre-action snapshot/events/RNG and advances revision exactly once from the pre-action revision.
- Godot public action/choice transaction capture, cancellation restore, failed-step rollback, RNG restore, and event-stream restore live in `VMTransactionManager`; `GameEngine` delegates the transaction boundary instead of owning snapshot mutation helpers.
- Godot public action post-dispatch settlement lives in `VMActionSettlement`; `GameEngine.apply_action` keeps pre-dispatch legality checks but delegates revision advance, failed-step rollback, ordinary KO settlement, cancellable trainer checkpoint storage, processed action-id recording, and winner/terminal normalization to the VM service.
- Godot choice response settlement lives in `VMChoiceSettlement`; `GameEngine.apply_choice` delegates the choice transaction, cancellation restore, continuation resume, attack finalize continuation, and post-choice KO settlement boundary to that VM service.
- Python optional VM/attack choices without an action checkpoint treat cancellation as an empty selection and continue the continuation stack, so optional attack choices still finalize the attack turn.
- Attack damage accumulation is stack-scoped through `ResolutionStack.context["attack_damage"]`; deprecated state bridge fields have been removed from production code.
- MBF-style modifier managers exist in Python and Godot with deterministic hook ordering.
- Python EventBus-backed MBF hooks now store explicit registration sequence numbers, so `MODIFY_DAMAGE`, `AFTER_DAMAGE`, `CAN_RETREAT`, and `POKEMON_KO` ordering is high-priority first and same-priority by registration order instead of relying on incidental sort stability.
- Python EventBus-backed rule hooks no longer swallow callback exceptions; hook failures become `EventBusError`/`ValueError` failures that VM/public action transaction boundaries can roll back instead of continuing with a partially applied rule state.
- Python choice continuations now have regression coverage proving post-choice settlement failures roll back to the pre-choice pending state, including state snapshot, exact `resolution_stack` data, RNG, action log, event stream, and emitted events.
- Godot choice continuations now have regression coverage proving post-choice KO trigger failures roll back to the pre-choice pending state, including state snapshot, exact `resolution_stack` data, RNG, event stream, and emitted events.
- Trigger results can be converted to VM commands instead of mutating board state directly.
- Snapshot/rollback tests cover state, pending choices, stack data, event stream, and RNG state; Python `GameSnapshot` now carries pending event-stream entries for clone/redo parity, and AI fair-search clones preserve pending resolution-stack/event-stream/action-log data while determinizing hidden zones.
- Python `SnapshotManager` undo/redo now has regression coverage proving pending resolution-stack frames, pending requests, nested stack context, and event-stream entries restore from deep-copied snapshots without aliasing the redo target.
- AI feature extraction has a compiled-IR path, with legacy effect strings kept as fallback inside the shared `engine.ai.effect_features` helper; AI business modules have structural coverage preventing direct raw `effect_type` field parsing.
- Python primitive command modules and DSL compiler factories have been split into focused combat, support, control, board, draw, recovery, search, energy, status, coin, and attack modules. The old `engine.commands.primitives` module remains a compatibility re-export.
- Python attack damage context mutation is isolated behind `engine.commands.attack_frames` helpers and backed only by stack context.
- Python max-HP and retreat-cost rule modifiers now delegate through `engine.effects.pokemon_stat_hooks` and `engine.effects.retreat_modifier_hooks`, aligning the Python oracle with the Godot `MAX_HP`/`CAN_RETREAT` MBF shape.
- Python `MODIFY_DAMAGE`, `CAN_RETREAT`, `AFTER_DAMAGE`, and `POKEMON_KO` hooks in `modifier_registration.py` register through `ModifierManager`; trigger hooks for reactive thorns, Miracle Energy, special-energy draw hooks, and Exp Share return explicit `command_specs` payloads that normalize to registered `trigger_*` VM command specs before execution; structural coverage rejects legacy `command`/`commands` trigger payload keys and direct board/event-payload mutation returning to trigger callbacks. Public and VM `ON_ATTACH` Jet Energy switching is collected through `ModifierManager.ON_ATTACH` and resolves through `trigger_switch_with_active`; runtime damage/KO trigger settlement consumes serializable command specs, and explicit `command_specs` payloads hard-fail during normalization when they contain object commands or non-list payloads.
- Python Exp Share `POKEMON_KO` hooks are side-effect-free with respect to event payloads; competing Exp Share trigger results declare an `exclusive_group`, and `command_specs_from_trigger_results` keeps the first stable-priority command spec instead of relying on hook-side payload mutation. Empty trigger payload groups do not block later payloads in the same group.
- Python trigger settlement now requires explicit `{op,args,branches}` trigger payloads to use registered `trigger_*` VM ops; legacy shorthand payloads such as `draw_cards` still normalize to `trigger_draw_cards`, but ordinary VM ops can no longer be smuggled through trigger `command_specs`.
- Python reactive-thorns ability registration is compiled-IR driven; the old Maushold ability-name fallback has been removed, and misleading raw ability effects no longer override `compiled_effects`.
- The old Python `engine.effects.modifier_registry` hardcoded modifier query module has been removed; damage, retreat, after-damage, KO, and attach modifier behavior now enters through MBF registration/trigger modules.
- Challenge AI can estimate compiled `deal_damage` commands with `formula_ast` directly before falling back to legacy effect-name heuristics.
- Challenge AI draw/productive-effect/static-value helpers use recursive compiled-IR feature extraction for `op/branches`, so nested command specs no longer need raw `effect_type` metadata to be valued.
- Challenge AI effect feature extraction treats VM `op` as authoritative when a dict contains both compiled IR and legacy raw metadata, and exposes compiled `branches` through the shared parameter view without double-counting recursive branches.
- Shared AI effect feature extraction treats VM `op` as authoritative for both params and branches: when compiled IR is present, legacy raw `params` and raw branch payloads are ignored so misleading raw metadata cannot affect Challenge AI or Deep AI features.
- Shared AI effect feature extraction now recognizes both dict-shaped VM payloads and object-shaped `CommandSpec` payloads; `op`/`args`/`branches` stay authoritative over legacy object `effect_type`/`params` metadata in Challenge AI and Deep AI feature paths.
- Python runtime/AI business modules now have structural coverage rejecting direct reads of raw or compiled effect fields such as `effects`, `trainer_effects`, `compiled_effects`, and `compiled_trainer_effects`; effect selection must enter through runtime effect selectors and shared feature helpers.
- Challenge AI card/search/action scoring now has regression coverage proving cards with authoritative `compiled_trainer_effects` receive the same heuristic value even when raw `trainer_effects` are intentionally misleading.
- Deep AI encoder action/card effect features and discard-cost estimation use recursive compiled-IR feature extraction instead of directly calling raw `effect_type`.
- Deep AI encoder tests now cover cards with misleading raw `trainer_effects` and authoritative `compiled_trainer_effects`, proving compiled IR tokens and discard-cost estimation override raw effect metadata.
- Deep AI training target filtering now has regression coverage proving custom-trainer availability checks receive authoritative `compiled_trainer_effects` instead of misleading raw `trainer_effects`.
- Godot compiled formula AST evaluation lives in `VMCombatFormula`; `EffectEngine` no longer owns the formula evaluator and has structural tests preventing it from returning to the facade.
- Python and Godot direct VM command tests cover `deal_damage + formula_ast` execution for hand size, energy counts, damage counters, discard counts, evolved counts, condition nodes, subtraction, division, and arithmetic composition; invalid formula parameters now hard-fail instead of silently evaluating to 0.
- Godot trainer/search request construction for Arven, Clara, Zinnia, Trekking Shoes, hand-bottom draw, conditional search, and generic search lives in `VMTrainerCommands`; shared card/confirmation request builders have moved out of `EffectEngine`.
- Godot energy attach/discard/relocate request construction and helper logic lives in `VMEnergyCommands`; continuations and look-top commands call through that module instead of `EffectEngine`.
- Godot board target selection, bench target selection, and switch request construction live in `VMBoardCommands`; combat-choice and board continuations call that module instead of `EffectEngine`.
- Godot zone mutation helpers for draw, selected-card movement, selected-card removal, discard events, and zone lookup live in `VMZoneHelpers`; trainer, energy, look-top, board, and combat VM modules no longer call those helpers through the `EffectEngine` facade.
- Godot generic card-selection and yes/no confirmation request builders live in `VMChoiceRequests`; trainer, look-top, and optional switch flows no longer call request-builder methods on the `EffectEngine` facade.
- Godot MBF/trigger hook scanners use `VMRuntimeEffects` for compiled-first effect selection and op-to-legacy aliasing; damage modifiers, MAX_HP, CAN_RETREAT, AFTER_DAMAGE, and POKEMON_KO tool checks no longer read raw card effect lists directly.
- Godot MBF/trigger hook scanners use `VMRuntimeEffects.strict_*` selectors for runtime rule hooks; raw-only trainer/ability payloads no longer drive MAX_HP, CAN_RETREAT, MODIFY_DAMAGE, AFTER_DAMAGE, or POKEMON_KO behavior when compiled IR is missing.
- Godot `GameEngine` runtime effect selection delegates through `VMRuntimeEffects` strict selectors; missing compiled payloads still become explicit `__missing_compiled_effect__` VM failures instead of falling back to raw effect execution.
- Godot availability/cost effect parsing delegates through `VMRuntimeEffects`; op-to-availability aliases, branch/arg param merging, effect-list normalization, and attack base-damage replacement detection no longer live in `GameEngine`.
- Godot concrete action cost, target availability, and stadium activation checks live in `VMAvailability`; `GameEngine` only selects the action's runtime effects and delegates the availability decision.
- Godot action cost, target availability, stadium activation, and attack base-damage replacement checks now consume runtime `compiled_effects` through an IR availability adapter; raw effects only remain as missing-compiled fallback metadata in those paths.
- Godot public action enumeration, setup action construction, retreat payment generation, stale action-reference validation, compiled-first action cost checks, and compiled-first target availability checks live in `VMActionAvailability`; `GameEngine.legal_actions` and pre-dispatch validation delegate to that service.
- Godot concrete public action execution for setup completion, playing/evolving Pokemon, attaching energy, playing trainers/tools/stadiums, using abilities, and retreating lives in `VMActionExecutor`; public action kind routing is registered through `VMActionDispatcher` instead of a `GameEngine` match table.
- Python `ActionResolver` now accepts direct VM command specs in normal and attack effect stacks, prefers dynamic `compiled_effects` / `compiled_trainer_effects` payloads when present, and keeps attack base-damage replacement, target availability, and explicit cost checks IR-aware.
- Python VM effect command construction, normal/attack `ResolutionStack` execution, attack final-damage frame injection, attack finish-turn frame injection, and attack base-damage replacement detection live in `VMEffectRunner`; `ActionResolver` keeps compatibility wrappers but no longer owns stack execution internals.
- Python `CardRegistry` now populates compiled attack, ability, and trainer VM payloads on in-memory card models; rule execution, legal action enumeration, static modifier hooks, Challenge AI, Deep AI encoder, and DL training filters read through shared compiled-first runtime effect helpers.
- Python rule execution, legal action enumeration, attack availability, rules validation, MBF/static hook registration, and on-enter-play helper paths use strict compiled runtime selectors; raw-only trainer/ability/attack payloads now produce explicit `__missing_compiled_effect__` sentinels or no hook match instead of driving the rules oracle, while AI/encoder helpers keep non-strict selectors only as migration-time heuristic fallback.
- Release card export no longer emits legacy damage formula VM ops; former formula-specific effects compile to generic `deal_damage` commands with `formula_ast`, condition nodes, and damage-context flags.
- `rules_golden.json` includes Python-generated pending attack choice continuation and cancellation cases; Godot validates the pending request metadata, continuation operation/data kind, stack shape, applies the fixture choice response, and compares the resumed final rule state.

## Current Closure Audit

1. Godot VM facade split: closed for the current runtime surface.
   - Evidence: `rules/effect_engine.gd` is a compatibility facade over `VMRuntime`; concrete command handlers, continuations, request builders, result helpers, trigger logic, and zone helpers live below `rules/vm/`.
   - Guardrail: Godot structural tests reject concrete handler prefixes, runtime registration helpers, result helper methods, facade module mirror fields, `weakref` facade wiring in VM modules, and request/zone helper methods returning to `EffectEngine`.

2. Attack settlement: closed for the current attack patterns.
   - Evidence: attack effects, final attack damage, KO-trigger settlement, pending attack choices, promotion-delayed completion, and end-turn finalization resolve through serializable stack frames in Python and Godot.
   - Guardrail: production state no longer exposes `_attack_damage_context` / `_finish_attack_after_promotions`; pending attack-choice golden fixtures compare `finish_attack_actor`, continuation operation, and continuation `data.kind`; Python structural coverage rejects old damage/KO post-processing wrappers returning to `ActionResolver`.

3. Formula AST migration: closed for release data.
   - Evidence: release damage formula compiler output exports as `deal_damage + formula_ast`, and Python/Godot VM tests cover constants, hand size, energy counts, damage counters, discard counts, evolution counts, condition nodes, subtraction, division, and nested arithmetic composition.
   - Guardrail: generated card data rejects legacy release formula ops; older formula ops remain compatibility adapters only.

4. MBF trigger migration: closed for implemented hook families.
   - Evidence: Python and Godot route `MODIFY_DAMAGE`, `AFTER_DAMAGE`, `CAN_RETREAT`, `MAX_HP`, `POKEMON_KO`, and `ON_ATTACH` families through modifier managers and registered `trigger_*` VM command specs.
   - Guardrail: structural tests reject direct state/event-payload mutation in Python trigger hooks, legacy `command`/`commands` payload keys, direct EventBus trigger registration, non-`trigger_*` explicit trigger specs, and direct board mutation inside Godot trigger collector/hook code.

5. Snapshot and rollback: closed for public actions, choices, AI clone, undo, and redo paths covered by the current test suite.
   - Evidence: Python and Godot transaction managers capture and restore game state, resolution stack, pending request, event stream, RNG state, and action logs where applicable; rollback tests cover failed public actions, failed attacks, failed choices, canceled trainer choices, optional attack choices, AI fair-search clones, and undo/redo snapshots.
   - Guardrail: cancellation with an action checkpoint restores the checkpoint, while optional VM/attack cancellation without a checkpoint continues the stack with an empty selection and still resolves required attack/turn frames.

6. AI migration: closed for Challenge AI, Deep AI encoding, and training target filtering.
   - Evidence: shared AI feature extraction treats compiled VM `op/args/branches` as authoritative, supports dict-shaped and object-shaped command specs, and confines legacy raw string fallback to `engine.ai.effect_features`.
   - Guardrail: structural tests reject direct raw `effect_type` parsing and direct `effects` / `trainer_effects` / `compiled_*effects` field access in AI business modules; regressions cover misleading raw effects paired with authoritative compiled IR.

## Future Expansion Rules

1. New runtime effects must enter through versioned compiled IR and registered VM command or continuation handlers.
2. New formula-like damage effects should compile to `deal_damage + formula_ast`; legacy formula ops are compatibility adapters, not preferred output.
3. New trigger families should register MBF hooks and return serializable `trigger_*` command specs instead of mutating board state in collectors.
4. New public action or choice boundaries must capture state, resolution stack, pending request, event stream, RNG state, and logs where applicable.
5. New AI heuristics should use compiled IR features or simulated deltas; raw metadata may remain only as an explicit fallback inside shared feature helpers.
