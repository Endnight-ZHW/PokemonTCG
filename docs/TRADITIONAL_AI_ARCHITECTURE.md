# PTCG 传统 AI 分层策略架构

发行版的 Challenge AI 使用规则战术、卡组策略与回合级浅层规划三层架构。Deep 模式在原生模型不可用时回退到同一套实现；运行时只有 Godot，Python 只生成策略配置并执行离线评估。项目不再包含旧 UCB/随机 rollout 决策引擎或运行时开关。

## 决策边界

`AIInformationSet` 是策略和规划器唯一允许使用的对局视图。它保留己方手牌、双方公开场面、弃牌区、牌张数量、公开历史、合法动作、公开卡组类型和比赛种子；隐藏双方牌库与奖赏卡身份、对手手牌身份、结算栈和私有日志。由信息集生成的信念状态只从发行牌表和公开信息重建，相同快照与种子必须得到相同结果。

Challenge 与 Deep 回退在创建对局、AI 入口、信息集、信念状态、搜索克隆和离线评估处都固定 `apply_type_matchups=false`。策略语义目录不会导出 `weaknesses`、`resistances` 或任何属性对位字段。卡牌 VM 原文明示的属性条件仍由规则引擎正常执行。Local 和 Network 模式继续使用各自的规则选项。

## 决策流水线

1. `AIMandatoryTactics` 处理唯一合法动作、确定性的立即获胜动作和合法的策略强制动作。
2. `AIStrategyRegistry` 根据公开卡组 key 选择专属策略；未知卡组使用 `GenericDeckStrategy`。
3. 策略根据当前阶段、公开资源和组合状态生成回合目标并为合法动作排序，根节点与每个搜索节点最多保留 6 个候选。
4. `AITurnBeamPlanner` 使用 beam 6、最多 6 个原子动作和总计最多 192 个节点规划本回合。叶节点最多检查 3 个高威胁对手即时回应；可解析的随机伤害使用期望值，其余随机或隐藏信息结果使用最多 3 个由比赛种子派生的可复现信念样本。
5. 评分合并胜负、奖赏交换、攻击达成、公开场面、资源效率、下回合准备度和当前卡组阶段目标。
6. `AICoordinator` 缓存语义动作意图。每次规则结算后都会复核 revision、actor、phase、公开状态指纹、前置条件和当前合法动作；选择或随机效果的实际公开分支若与计划指纹不同，会丢弃剩余计划并局部重规划，相同分支则安全复用。

普通规划软时限为 850ms，协调器硬时限为 1100ms。取消、强制战术、选项解析、候选排序和信念样本共享同一端到端预算；截止时只能返回已经确认合法的当前最佳动作。缓存命中仍会先检查新出现的强制战术。

## 卡组策略

静态配置的唯一来源是 `python/data/ai_strategy_definitions.py`，由导出脚本生成 `godot/data/ai_strategies.json`。配置包含版本、阶段目标、卡牌角色、动作权重、公开对局修正和对应 GDScript hook 哈希；配置或 hook 任一变化都会改变策略指纹。

十套发行卡组分别绑定独立脚本：

- Fire：烈焰猴进化链、火能量密度、回收和稳定/爆发路线。
- Water：甲贺忍蛙与宝石海星协同、铺伤、狙击和奖赏路线。
- Psychic：天然鸟/克雷色利亚加速、手牌能量保留和关键回合准备。
- Lightning：电龙、发电机与皮卡丘的充能速度、概率和资源风险。
- Fighting：路卡利欧自伤安全、能量爆发和能量转移。
- Colorless：鼠家族场面、手牌规模和特殊能量。
- Dragon：七夕青鸟治疗/保护、双属性能量和大奶罐防守价值。
- Grass：宽铺进化、土台龟规模收益、树林龟/萨戮德/菜种花园。
- Steel：青铜钟转能、苍响、藏玛然特和大钢蛇的攻防节奏。
- Darkness：嘟嘟利自伤、长毛狗、黑暗补丁和阿勃梭鲁的资源/奖赏节奏。

策略只接收深只读的信息集、序列化合法动作或 ChoiceView，以及脱敏后的卡牌语义。Choice 评分必须区分检索、受益选择、弃牌和其他成本语境；攻击评分使用 `attack_index`，不能把同一宝可梦的不同招式视为相同动作。

## 扩展新卡组

1. 在 Python 定义中加入卡牌角色、三个阶段目标、基础权重与公开 archetype 标签。
2. 新建继承 `DeckStrategy` 的 GDScript hook，只使用公开信息实现阶段、状态和动作差分。
3. 在 `AIStrategyRegistry` 注册 `strategy_id`。
4. 运行 `python python/scripts/export_godot_data.py` 更新 JSON，再用 `--check` 验证生成物。
5. 为该卡组加入 8–12 个战术金标，至少覆盖展开、进化、检索、换位、攻击、奖赏路线、资源保留和败局规避。

缺少专属注册的自定义卡组会自动使用通用语义策略。评估器只接受 `turn_beam_v1`；旧引擎 ID 和未知引擎 ID 都会显式失败，不能静默路由到新 AI。

## 验证与评估

`tools/test_godot_ai.ps1` 执行信息边界、语义隔离、十卡组注册、不少于 100 个策略金标、合法动作、Choice、随机效果、取消、计划缓存和十套实局冒烟。`tools/test_python.ps1 -Tier core` 验证配置、hook 指纹、导出和评估报告。

PR CI 运行上述 AI 冒烟及 evaluator smoke。定时 CI 使用 Balanced preset：10×50×2=1000 局同卡组镜像，加上 10×9×10×2=1800 局有方向交叉对局，共 2800 局。默认任务由同一新引擎换席自检，验证复现性、合法性、规则隔离、性能和矩阵完整性；比较两份新策略配置时使用等价性门禁，不再加载固定旧 Challenge AI。

跨卡组局按“同种子四局角色交叉块”组织。对每个无序卡组对 X/Y 和种子块，依次执行 A(X) 对 B(Y) 的两局换席，以及 A(Y) 对 B(X) 的两局换席；四局共用同一个对局种子和强制先手编号。这样 A、B 都分别使用 X/Y，各自先手、后手次数相同，同一卡组也分别经过玩家 0/1 的两条洗牌随机流。正式验证器强制检查 45 个无序卡组对×10 个种子块×4 局完整闭合，避免把单一卡组强度、起手质量或先后手优势误当作 AI 优势。

极端情况下，即使 X 因卡组强度或对局关系而无论先后手都必败于 Y，闭合块仍会得到 A(X) 对 B(Y) 两负、A(Y) 对 B(X) 两胜，合计 2/4=50%，不会惩罚恰好先驾驶弱卡组的一方。单个方向的 0% 或 100% 只描述卡组对局，不单独用于判断 AI 强弱。

每局相对候选 A 计分：胜 1 分、平 0.5 分、负 0 分，点数率为 `(胜场 + 0.5×平局) / 干净对局数`。报告分别列出镜像点数率、跨卡组角色交叉调整点数率和全部 2800 局总点数率；单个有利/不利跨卡组格子不作为纯 AI 强度结论。评估 schema v4 记录 `type_matchups=false`、四局块标识、逐次真实决策耗时、缓存命中耗时和完整 AI 回合耗时，并把规则与十套策略内容写入结果指纹。

Windows 门槛为普通决策 p95≤900ms、缓存复用 p95≤100ms、完整 AI 回合 p95≤1.5s；Android 分别为 1000ms、200ms 和 2s。结果不得包含超时非法动作。跨卡组的单卡组原始胜率会混入卡组固有强弱，只作实战矩阵展示，不作为该套策略的独立门槛。

## 当前接受状态

2026-07-22，产品决策直接接受当前新架构，旧 AI 对比所用的一次性 55%/48% 强度门禁随旧基线一同退役；这不是把未达到的比较门槛记为通过。清理前最后一轮 600 局确认集使用 seed 17、每套牌 3 个镜像种子块、每个无序卡组对 3 个四局交叉块，结果为 321 胜、2 平、277 负，原始点数率 53.67%；镜像点数率 50.00%，跨卡组交叉点数率 54.07%，按原 2800 局构成折算为 52.62%。

该轮 600/600 对局均干净完成，122/122 金标通过，非法动作、Choice 失败、规则异常和动作上限耗尽均为 0，`type_matchups=false`。Windows 策略 A 的普通决策、缓存复用和完整 AI 回合 p95 分别为 854.868ms、46.710ms 和 1239.446ms，满足既定性能门槛。原始分片和大体积结果属于可再生中间文件，清理后仅保留本节摘要。
