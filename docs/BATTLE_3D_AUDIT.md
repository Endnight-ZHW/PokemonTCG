# 三维对战细节检查 · 2026-09-13

本轮在实际 OpenGL 渲染下检查了 1600×900、1280×720、900×540、2000×900，
并检查 900×540 加 48px 安全区的布局。覆盖满备战区、20 张手牌、多附件、复合状态、
空竞技场、奖赏牌堆、公开展示、连续硬币、强制选择、详情、弹窗与动画模式。

| 问题 | 修复后的行为 |
| --- | --- |
| 多附件向下展开遮住备战卡，道具可能被六层上限截掉 | 压缩露出的纸边，预留道具层；精确数量继续由 HUD 显示 |
| HP、伤害、能量、状态和道具沿用二维位置，窄屏互相遮挡 | 根据三维卡面的投影排布，窄屏复合状态合并为“异”；详情保留完整状态 |
| 小屏卡面上的操作提示遮住数值 | 合法目标由三维轮廓标记，操作说明显示在顶部任务栏 |
| 手牌滚动裁切后仍有高亮线残留 | 卡面、纸边、高亮和接触阴影使用相同的裁切范围 |
| 已隐藏、已拖走或滑出浏览窗口的卡仍能被点击 | 精确射线和 48px 触控扩展都只接受可见表面，重叠优先实际卡面 |
| 奖赏点击沿用旧二维绘制顺序，选到下层卡 | 从实际三维命中层取得物理索引；空出的奖赏空间不再响应 |
| 宽屏边缘牌堆超出区域，数量标签悬空 | 保持卡牌比例，将投影轮廓约束到牌堆区域，数量标签跟随投影 |
| 缩小窗口后密集手牌丢失正在浏览的位置 | 按视觉身份及原窗口中的相对位置恢复浏览区域 |
| 牌区取消、失焦或重新绑定后，迟到的松手事件仍触发操作 | 牌区纳入统一取消流程；越过移动阈值后返回原点也不会误点 |
| 牌区长按要等松手，且与卡牌的多指去重不一致 | 350ms 到时打开详情，抬手不再次触发；真实触控与模拟鼠标去重 |
| 公开展示时新生成的徽章穿过遮罩 | 遮罩持续接纳新节点，结束时恢复，及时移除已释放节点的记录 |
| 发放奖赏时多张飞牌落向同一位置，牌堆接触前后尺寸跳变 | 分别保留奖赏落点，并复用实际牌堆的三维起止姿态 |
| 空竞技场缺少三维落牌提示 | 空牌位显示轮廓，并使用同一套三维拾取 |

新增回归检查位于 `godot/tests/battle_3d_interaction_checks.gd`，由三维契约运行。
覆盖每张奖赏露出边缘的索引、牌堆起止姿态、隐藏输入、取消、HUD 遮罩重建、
多尺寸附件与徽章不相交、空竞技场，以及牌区真实触控与模拟事件去重。
`battle_usability_contract` 另覆盖窗口缩放的手牌身份保持和移动后返回原点的取消行为。

在 Godot 中运行 `res://tools/ui_workbench.tscn`（F6），点击“三维细节检查”可重复查看
满场、20 张手牌、多附件及复合状态。现有事件按钮继续重放抽牌、附能、进化等动画。

可重复生成截图：

```powershell
.\tools\test_battle3d_graphics.ps1
# 另运行 ui_preview.gd -- --battle-usability-only，包含安全区和本轮复杂场景。
```

已通过 Godot 契约、真实图形与完整 UI 预览、10 套 Challenge 卡组终局、LAN/Relay
完整对局及代码边界检查。RTX 4070 Ti、1920×1080 压力探针的 P95 为高 16.673ms、
中 16.673ms、低 33.350ms，采样点绘制调用为 308 / 308 / 209。
这些结果来自桌面图形设备；Android 真机触控、持续帧率及温升仍待接入设备验收。

Windows 与 Android 调试包已重新导出。Windows 启动、原生运行库、网络与发布契约
烟雾检查通过；Android APK 元数据和 ARM64 载荷检查通过，设备运行检查因未连接真机跳过。
